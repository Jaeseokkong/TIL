# 📦 번들 사이즈 최적화 전략

번들 사이즈가 커질수록 다운로드·파싱·실행 시간이 늘어나 초기 로딩 성능이 저하됩니다.

---

## 1️⃣ 대표 전략

- **코드 스플리팅** - 라우트/컴포넌트 단위로 번들을 나눠 필요한 시점에 로드
- **Tree Shaking** - 사용하지 않는 코드 제거 (ESM, side-effect free 패키지 필요)
- **의존성 다이어트** - 무거운 라이브러리를 경량 대안으로 교체 (예: moment → dayjs)

---

## 2️⃣ 예시 코드

```tsx
// 동적 import로 코드 스플리팅
import { lazy, Suspense } from "react";

const Chart = lazy(() => import("./Chart"));

function Dashboard() {
  return (
    <Suspense fallback={<Spinner />}>
      <Chart />
    </Suspense>
  );
}
```

- 번들 분석: `webpack-bundle-analyzer`, Next.js는 `@next/bundle-analyzer`로 시각화 가능

---

## 3️⃣ 체크리스트

- [ ] 사용하지 않는 라이브러리/코드 제거
- [ ] 큰 라이브러리는 필요한 부분만 import (`import { debounce } from "lodash-es"`)
- [ ] 초기 화면에 불필요한 컴포넌트는 lazy 처리

---

## ✍️ 한 줄 정리

> **번들 최적화는 코드 스플리팅, 트리 셰이킹, 가벼운 의존성 선택을 조합해 초기 로딩에 필요한 JS 양을 줄이는 작업이다.**
