# ⏳ React Testing Library로 비동기 UI 테스트하기

API 호출 이후 화면이 바뀌는 컴포넌트를 테스트할 때는, 렌더링이 끝나는 시점을 **기다려주는 API**가 필요합니다.

---

## 1️⃣ findBy* - 비동기 요소 대기

```jsx
test("로딩 후 사용자 이름이 표시된다", async () => {
  render(<UserProfile userId={1} />);

  const name = await screen.findByText("재석");
  expect(name).toBeInTheDocument();
});
```

- `findBy*`는 내부적으로 요소가 나타날 때까지 재시도(기본 1초)하는 Promise 기반 쿼리
- `getBy*`는 즉시 없으면 실패, `queryBy*`는 없어도 null 반환(존재하지 않음을 검증할 때 사용)

---

## 2️⃣ waitFor로 임의의 조건 기다리기

```jsx
await waitFor(() => {
  expect(mockFetch).toHaveBeenCalledTimes(1);
});
```

- 특정 DOM 요소가 아니라 **임의의 조건**(mock 호출 여부 등)을 기다릴 때 사용
- API 호출은 MSW(Mock Service Worker) 등으로 가짜 응답을 만들어 실제 네트워크 없이 테스트

---

## 3️⃣ 자주 하는 실수

- `act` 경고를 피하려고 무작정 `await new Promise(r => setTimeout(r, 1000))` 사용 → 테스트가 느려지고 불안정해짐
- `findBy*`/`waitFor`처럼 **조건 기반으로 기다리는 API**를 우선 사용하는 것이 안정적

---

## ✍️ 한 줄 정리

> **비동기 UI 테스트는 임의의 sleep 대신 findBy*/waitFor로 실제 조건이 충족될 때까지 기다리도록 작성해야 안정적이다.**
