# 🧪 통합 테스트 vs 단위 테스트

테스트 범위에 따라 단위(Unit)와 통합(Integration) 테스트로 나뉘며, 목적과 장단점이 다릅니다.

---

## 1️⃣ 비교

| 구분 | 단위 테스트 | 통합 테스트 |
|------|-------------|-------------|
| 범위 | 함수/컴포넌트 하나 | 여러 모듈의 상호작용 |
| 속도 | 빠름 | 상대적으로 느림 |
| 외부 의존성 | Mock으로 대체 | 실제(또는 유사한) 의존성 사용 |
| 목적 | 로직의 정확성 검증 | 모듈 간 연동 검증 |

---

## 2️⃣ 예시 코드 (Jest)

```js
// 단위 테스트 - 순수 함수
test("합계를 계산한다", () => {
  expect(sum(1, 2)).toBe(3);
});

// 통합 테스트 - API + DB 연동
test("주문 생성 시 재고가 차감된다", async () => {
  await request(app).post("/orders").send({ itemId: 1, qty: 2 });
  const item = await db.item.findById(1);
  expect(item.stock).toBe(8);
});
```

- 테스트 피라미드: 단위 테스트를 가장 많이, 통합·E2E는 핵심 흐름 위주로 적게 작성

---

## ✍️ 한 줄 정리

> **단위 테스트는 개별 로직을, 통합 테스트는 모듈 간 연동을 검증하며 둘의 비율은 테스트 피라미드 원칙을 따르는 것이 좋다.**
