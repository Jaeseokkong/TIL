# 🧵 Node.js Event Loop와 libuv 스레드 풀

Node.js는 싱글 스레드로 JS 코드를 실행하지만, 내부적으로는 **libuv가 제공하는 스레드 풀**을 활용해 무거운 작업을 처리합니다.

---

## 1️⃣ 왜 스레드 풀이 필요한가

- JS 실행 자체는 싱글 스레드지만, 파일 I/O·DNS 조회·일부 crypto 연산 등은 **OS 커널이 비동기를 지원하지 않는 경우**가 많음
- 이런 작업을 libuv가 **백그라운드 스레드 풀(기본 4개)**에 위임해 처리하고, 끝나면 콜백을 이벤트 루프에 넘겨줌

---

## 2️⃣ 예시 - fs 모듈

```js
const fs = require("fs");

fs.readFile("big-file.txt", () => {
  console.log("파일 읽기 완료"); // 스레드 풀에서 처리 후 콜백 실행
});

console.log("다음 코드는 먼저 실행됨");
```

- `fs.readFile`은 실제 파일 읽기를 스레드 풀의 워커 스레드에 위임하고, 메인 스레드는 곧바로 다음 코드를 계속 실행

---

## 3️⃣ 스레드 풀 크기 조정

```bash
UV_THREADPOOL_SIZE=8 node app.js
```

- 기본값은 4로, 동시에 처리해야 할 I/O/crypto 작업이 많은 서버라면 환경변수로 늘릴 수 있음 (최대 128)
- 다만 CPU 코어 수를 크게 넘기면 컨텍스트 스위칭 비용만 늘어날 수 있어 무작정 키우는 것은 주의

---

## 4️⃣ 오해하기 쉬운 점

- "Node.js는 싱글 스레드"라는 말은 **JS 실행 컨텍스트**에 한정된 이야기이고, 내부적으로는 libuv가 여러 스레드를 활용
- 순수 CPU 연산(암호화, 이미지 처리 등 JS로 직접 계산하는 작업)은 스레드 풀의 도움을 받지 못해 여전히 메인 스레드를 블로킹함 → 이런 경우는 Worker Threads가 더 적합

---

## ✍️ 한 줄 정리

> **Node.js는 JS 실행은 싱글 스레드지만, 파일 I/O 등 일부 작업은 libuv의 스레드 풀에 위임해 처리하며 순수 CPU 연산은 여전히 메인 스레드를 막는다.**
