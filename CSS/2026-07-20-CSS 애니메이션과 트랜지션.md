# 🎞️ CSS 애니메이션과 트랜지션

CSS만으로 상태 변화에 움직임을 부여하는 두 가지 방법, **transition**과 **animation**의 차이를 정리합니다.

---

## 1️⃣ Transition vs Animation

| 구분 | transition | animation |
|------|-----------|-----------|
| 트리거 | 상태 변화(hover, class 변경 등) 필요 | 자동 실행 가능 |
| 반복 | 불가능 | `animation-iteration-count`로 반복 가능 |
| 중간 단계 | 시작~끝 값만 지정 | `@keyframes`로 여러 단계 지정 가능 |

👉 단순한 상태 전환은 transition, 복잡하고 반복적인 움직임은 animation이 적합합니다.

---

## 2️⃣ 예시 코드

### transition

```css
.button {
  background: #4f46e5;
  transition: background 0.2s ease-in-out;
}
.button:hover {
  background: #4338ca;
}
```

### animation

```css
@keyframes fadeInUp {
  from { opacity: 0; transform: translateY(10px); }
  to { opacity: 1; transform: translateY(0); }
}

.card {
  animation: fadeInUp 0.4s ease-out forwards;
}
```

---

## 3️⃣ 성능 팁

- `transform`, `opacity`는 GPU 가속 대상이라 리플로우 없이 부드럽게 동작
- `width`, `top`, `left` 등을 애니메이션하면 레이아웃 재계산(reflow) 발생 → 가급적 transform으로 대체

---

## 4️⃣ 접근성 고려 - prefers-reduced-motion

일부 사용자는 화면의 움직임에 어지러움을 느낄 수 있어, 미디어 쿼리로 애니메이션을 줄여줄 수 있습니다.

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

---

## ✍️ 한 줄 정리

> **상태 변화에 반응하는 단순한 전환은 transition, 반복·다단계 움직임은 animation을 사용하고, 성능을 위해 transform/opacity 위주로 애니메이션한다.**
