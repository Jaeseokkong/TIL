# 🗃️ Next.js 캐싱 전략 (fetch cache, revalidate)

Next.js App Router는 `fetch` 호출 단위로 캐싱 동작을 세밀하게 제어할 수 있습니다.

---

## 1️⃣ 기본 캐싱 옵션

```ts
// 기본값: 정적으로 캐싱 (빌드 시점 데이터로 고정)
fetch("https://api.example.com/data");

// 매 요청마다 새로 가져오기
fetch("https://api.example.com/data", { cache: "no-store" });
```

- 별도 옵션이 없으면 Next.js는 가능한 경우 요청 결과를 캐싱해 정적 페이지처럼 취급

---

## 2️⃣ 시간 기반 재검증 - revalidate

```ts
fetch("https://api.example.com/data", { next: { revalidate: 60 } });
```

- 60초마다 백그라운드에서 새 데이터를 가져와 캐시를 갱신 (ISR과 유사한 동작)
- 페이지/레이아웃 단위로도 `export const revalidate = 60`으로 동일하게 설정 가능

---

## 3️⃣ 태그 기반 무효화 - revalidateTag

```ts
fetch("https://api.example.com/posts", { next: { tags: ["posts"] } });

// 서버 액션 등에서 특정 태그만 즉시 무효화
import { revalidateTag } from "next/cache";
revalidateTag("posts");
```

- 게시글 작성/수정 직후처럼 **특정 이벤트가 발생했을 때만** 관련 캐시를 즉시 갱신하고 싶을 때 사용

---

## ✍️ 한 줄 정리

> **Next.js는 fetch 옵션(cache, revalidate, tags)만으로 정적 캐싱·주기적 재검증·이벤트 기반 무효화를 모두 세밀하게 제어할 수 있다.**
