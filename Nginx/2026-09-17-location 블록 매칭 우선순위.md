# 🧭 Nginx location 블록 매칭 우선순위

같은 요청 경로에 여러 `location` 블록이 매칭될 수 있을 때, Nginx가 **어떤 순서로 우선순위를 정하는지** 정리합니다.

---

## 1️⃣ 매칭 우선순위 (높은 순)

1. `location = /path` - 정확히 일치 (Exact Match)
2. `location ^~ /path` - 접두사 일치 중 최우선 (정규식 검사 생략)
3. `location ~ /path` / `location ~* /path` - 정규식 일치 (대소문자 구분/무시)
4. `location /path` - 일반 접두사 일치 (가장 긴 것이 우선)

---

## 2️⃣ 예시

```nginx
location = /login { ... }      # /login 요청에만 정확히 매칭
location ^~ /static/ { ... }   # /static/ 으로 시작하면 정규식 검사 없이 바로 매칭
location ~ \.php$ { ... }      # .php로 끝나는 요청
location / { ... }             # 나머지 모든 요청 (기본값)
```

- `^~`를 캐시/정적 파일 경로에 자주 사용 - 정규식 매칭을 건너뛰어 처리 속도도 약간 더 빠름

---

## 3️⃣ 자주 하는 실수

- 일반 접두사 `location`끼리는 **더 긴(구체적인) 경로가 우선**한다는 걸 놓치고, 선언 순서가 우선이라고 착각하는 경우가 많음
- 정규식 `location`은 선언된 순서대로 검사해서 **처음 매칭되는 것**을 사용하므로, 순서가 중요함

---

## ✍️ 한 줄 정리

> **Nginx location은 정확 일치 → ^~ 접두사 → 정규식 → 일반 접두사(가장 긴 것) 순으로 우선순위가 정해진다.**
