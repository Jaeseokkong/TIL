# 🌐 CORS 에러 해결 경험

프론트엔드에서 다른 origin의 API를 호출할 때 발생한 CORS 에러를 원인별로 정리합니다.

---

## 1️⃣ CORS가 발생하는 이유

브라우저는 보안을 위해 **Same-Origin Policy**를 기본으로 적용하며,
다른 origin(프로토콜/도메인/포트 중 하나라도 다름)으로의 요청은 서버가 명시적으로 허용해야 합니다.

```
Access to fetch at 'https://api.example.com' from origin 'https://myapp.com'
has been blocked by CORS policy
```

---

## 2️⃣ 자주 만난 원인

- 서버에서 `Access-Control-Allow-Origin` 헤더 미설정
- `credentials: "include"`로 쿠키를 보낼 때 서버가 `*`가 아닌 **정확한 origin**을 명시해야 함
- Preflight(`OPTIONS`) 요청에 대해 서버가 응답하지 않음 (커스텀 헤더/PUT·DELETE 사용 시 발생)

```js
fetch("https://api.example.com/user", {
  method: "GET",
  credentials: "include", // 쿠키 포함 시 서버 CORS 설정이 더 까다로워짐
});
```

---

## 3️⃣ 해결 방법

- 서버 측에서 허용 origin, 메서드, 헤더를 명시적으로 설정
- 개발 환경에서는 프론트 서버에 **프록시**를 두어 CORS 자체를 우회 (Next.js `rewrites`, Vite `server.proxy` 등)

---

## ✍️ 한 줄 정리

> **CORS는 브라우저의 보안 정책이며, 서버가 허용 origin·메서드·헤더를 정확히 설정해야 해결되고 개발 단계에서는 프록시로 우회할 수 있다.**
