# 🔗 배열 고차함수(map/filter/reduce) 체이닝 최적화

`map`, `filter`, `reduce`를 이어붙이면 가독성은 좋지만, **배열을 여러 번 순회**하게 되는 비용도 함께 생각해야 합니다.

---

## 1️⃣ 체이닝의 비용

```js
const result = items
  .filter((i) => i.active)
  .map((i) => i.price)
  .reduce((sum, price) => sum + price, 0);
```

- `filter`, `map`, `reduce`가 각각 배열을 한 번씩 순회 → 총 3번 순회 (O(3n))
- 데이터가 작다면 문제없지만, 대량 데이터에서는 순회 횟수를 줄이는 게 유리

---

## 2️⃣ reduce 하나로 합치기

```js
const result = items.reduce((sum, i) => {
  return i.active ? sum + i.price : sum;
}, 0);
```

- 조건 체크와 누적을 한 번의 순회(O(n))로 처리
- 다만 가독성이 떨어질 수 있어, **성능이 실제로 중요한 구간에서만** 이런 최적화를 고려하는 것이 좋음
