# 🗃️ JavaScript Set과 Map 활용

배열/객체만으로는 번거로운 "중복 제거"와 "임의 키-값 저장"을 더 명확하게 표현할 수 있는 ES6 자료구조입니다.

---

## 1️⃣ Set - 중복 없는 값의 집합

```js
const unique = [...new Set([1, 2, 2, 3, 3, 3])]; // [1, 2, 3]

const setA = new Set([1, 2, 3]);
const setB = new Set([2, 3, 4]);
const intersection = [...setA].filter((x) => setB.has(x)); // [2, 3]
```

- 배열의 `includes`는 O(n)이지만, `Set.has`는 평균 O(1)이라 중복 체크가 잦을 때 유리

---

## 2️⃣ Map - 어떤 타입이든 키로 사용

```js
const map = new Map();
const keyObj = { id: 1 };

map.set(keyObj, "객체를 키로 사용");
map.set("plain", "문자열도 가능");

map.get(keyObj); // "객체를 키로 사용"
```

- 일반 객체(`{}`)는 키가 항상 문자열/심볼로 강제 변환되지만, `Map`은 **객체나 함수 등 어떤 값도 키로 사용 가능**
- 삽입 순서를 보장하고, `size` 속성으로 개수를 바로 확인 가능 (객체는 `Object.keys(obj).length` 필요)

---

## 3️⃣ 언제 일반 객체 대신 Map/Set을 쓸까

| 상황 | 추천 |
|------|------|
| 키가 문자열이 아니거나, 동적으로 키가 계속 추가/삭제됨 | Map |
| 값의 유무만 빠르게 확인하거나 중복 제거가 필요할 때 | Set |
| 단순히 고정된 필드를 가진 데이터 구조 | 일반 객체 |

---

## ✍️ 한 줄 정리

> **Set은 O(1) 수준의 중복 체크에, Map은 어떤 타입이든 키로 쓸 수 있고 순서를 보장하는 키-값 저장이 필요할 때 일반 객체보다 유리하다.**
