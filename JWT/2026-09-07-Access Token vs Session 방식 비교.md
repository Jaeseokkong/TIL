# 🆚 Access Token(JWT) vs Session 방식 비교

로그인 상태를 유지하는 대표적인 두 방식의 차이를 정리합니다.

---

## 1️⃣ 동작 방식

| 구분 | Session | JWT (Access Token) |
|------|---------|----------------------|
| 상태 저장 위치 | 서버 (세션 저장소) | 클라이언트 (토큰 자체에 정보 포함) |
| 서버 확장성 | 세션 공유 필요 (Sticky Session, Redis 등) | Stateless라 확장이 쉬움 |
| 즉시 무효화 | 서버에서 세션 삭제하면 즉시 무효화 | 만료 전까지는 무효화가 어려움 |

---

## 2️⃣ 각각의 장단점

- **Session**: 서버가 상태를 갖기 때문에 로그아웃/강제 만료가 즉시 반영됨, 다만 서버 인스턴스가 여러 대면 세션 공유 인프라가 필요
- **JWT**: 서버가 상태를 갖지 않아 수평 확장에 유리, 다만 토큰이 탈취되면 만료 전까지 막기 어려움 (블랙리스트 관리로 보완 가능)

---

## 3️⃣ 실무에서의 선택

- 단일 서버, 즉각적인 무효화가 중요한 서비스 → Session
- 여러 서버/마이크로서비스로 확장해야 하는 서비스 → JWT + 짧은 만료 + Refresh Token 조합

---

## ✍️ 한 줄 정리

> **Session은 즉각적인 무효화에 강하고 JWT는 서버 확장성에 강하며, 실무에서는 서비스 구조에 따라 선택하거나 JWT에 Refresh Token을 더해 단점을 보완한다.**
